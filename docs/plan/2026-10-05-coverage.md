# Coverage to 100 %, with performance and space (from 5 October 2026)

The owner's order of 5 October: every feature and test suite covered, the usability
issues, integration and scaling across machines, with performance and space as
high-value targets at each abstraction level; only then the fair benchmark (licences,
all test cases, Draco). This plan is the inventory and the order. Done work goes to
[STATUS.md](../STATUS.md); performance work is logged in
[design/performance.md](../design/performance.md) §6.

## 1. Who owns what

Every gap below names its owner, so a slice lands where the concept lives and nothing
is implemented twice.

| Crate | Owns |
|---|---|
| `nrese-rdf`, `nrese-rdf-io` | terms, IRIs; every RDF syntax, parse and write, error recovery |
| `nrese-xsd` | datatypes: value spaces, lexical mapping, facets, and the value-space operations the datatype theory needs (comparisons and intervals within a space, which spaces overlap) |
| `nrese-sparql-syntax`, `nrese-sparql`, `nrese-sparql-results` | SPARQL parse and algebra; evaluation, planning, GeoSPARQL and text functions; result formats |
| `nrese-exec` | operators, budgets, the process memory limit |
| `nrese-engine` | dictionary, index (permutations, packing), durability, bulk loads, statistics |
| `nrese-reasoner` | rule reasoning: rulesets, batch and delta executors, equality, explanations of rule inferences |
| `nrese-owl` | the OWL 2 structural model, its reading and writing, normalisation into DL-clauses, proofs and justifications |
| `nrese-dl` | DL engines: the context core, the hypertableau, the datalog bounds, **the datatype theory** (design owl2-dl.md: satisfiability of a conjunction of data ranges with counts); classification and realisation |
| `nrese-shacl`, `nrese-vector` | SHACL validation; vector indexes and kernels |
| `nrese-store` | the service: transactions, catalog and repositories, how reasoning, SHACL and the DL engine run against the store |
| `nrese-server` | HTTP, protocols, authentication and access, the engine API, the console |

Boundaries the next slices cross, fixed now:
- **Datatypes in DL** (3.5): the datatype theory is `nrese-dl`'s, as the design has it;
  it decides data-range satisfiability with counts over `nrese-xsd`'s value spaces, and
  value-space operations missing there are added there, not in `nrese-dl`. `nrese-owl`
  only represents data ranges.
- **Keys**: `nrese-owl` reads `HasKey` and normalises it to DL-safe rules over named
  individuals; `nrese-dl` applies them; `nrese-reasoner` keeps its RL key rule.
- **Classification** (3.4): `nrese-dl` owns the driver (known and possible subsumers,
  model merging); `nrese-store` exposes it per repository; `nrese-server` keeps
  `/classification`.
- **Distribution** (G6): `nrese-engine` owns partitions and replicas of the index;
  `nrese-store` owns routing a request; `nrese-server` the cluster protocol. Reasoning
  across partitions goes through `nrese-reasoner`'s batch executor's inputs, not around
  them.

## 3. Reasoning

- **OWL 2 DL:** datatypes (3.5) and keys first: they hold the most open tests. Then
  classification and realisation (3.4) against ELK and Konclude. Then the store's DL mode:
  certain answers with the bounds, consistency on commit, explanations through the proof
  IR.
- **Performance of the context core** (3.1): 9 times slower than the EL classifier in
  saturation.
- **OWL 2 QL** by query rewriting beside materialisation: existentials on the right of
  `SubClassOf` are not materialised now, so certain answers through them are missing.
- **Equality:** incremental merges and splits; late expansion through named graphs and
  the inferred model.

## 4. Features and workloads

From the suite's matrix (`suite.py nrese`): every capability runs, but these workloads
are planned or partial. Each needs its kit, and NRESE's gaps found by it fixed:
LDBC SPB (reasoning with continuous updates, GraphDB's audited benchmark), sparqloscope,
BSBM, WatDiv, ERA SHACL, full-text search, federation (planned); GeoSPARQL, ORE 2015, the
RG×GS×GND integration (partial); real ontologies, consistency, OWL2Bench classification
(planned). Plus G5 vector search (codecs, Vamana, embeddings in the store), G4 planning
(characteristic sets, aggregates over products), G7 (error recovery in the RDF/XML and
JSON-LD parsers, multi-architecture images, HTTP soak and fuzzing).

**Property graphs** (owner, 5 October): the cloud graph offerings serve labelled property
graphs (Amazon Neptune: openCypher and Gremlin, openCypher over RDF through OneGraph; Google
Spanner Graph: ISO GQL and SQL/PGQ, graph algorithms), and neither reasons over OWL. NRESE
serves property graphs over the same store, with reasoning: a mapping onto RDF 1.2 (edge
properties on reifiers), ISO GQL and an openCypher subset compiled to the same algebra,
paths and composite values as results, graph algorithms, LPG import formats, LDBC SNB as the
workload. Design first, from research.

## 6. Scale across machines (G6)

H1-H7 of the hardware plan: hardware profiles, SIMD kernels, NUMA and morsels, larger than
RAM (spilled reasoning working sets, mapped indexes), GPUs where a workload gains, read
replicas, and partitioning with distributed query and reasoning. This is the area with
the least design behind it: §7 of the research list.
