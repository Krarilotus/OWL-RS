# Step 2: `nrese-rdf` and `nrese-xsd` against `oxiri`, `oxrdf` and `oxsdatatypes`

1 October 2026. Main PC: AMD Ryzen 7 7800X3D, 64 GB, Windows 11. Rust 1.98.1, release
profile, fat LTO, one codegen unit. `cargo run --release --bin bench`; each case is the
median of 9 runs over the same inputs (seeded generators), in nanoseconds per item.

Geometric mean of the ratios: 0.43.

**Where a ratio is above 1.**
- `xsd:double` parse: within measurement noise. Both are Rust's own parser; ours adds a
  check of the result, and is at 1.08 of a bare `f64` parse.
- `dateTime` compare: within noise at about one nanosecond, where the loop itself
  dominates. Both compare a stored 128-bit instant.
- Parsing generated IRI references: about 10% slower on random, mostly invalid text; on
  valid absolute IRIs ours is 2.5 times as fast.

**Robustness.** oxrdf's canonicalisation overflows a 1 MiB stack (the Windows main thread)
on the chain; the benchmark runs both on a thread with a 1 GiB stack. Ours needs no deep
recursion: it recurses only where it must choose (see `crates/rdf/nrese-rdf/src/canonical.rs`).

**What got the numbers here** (from first versions that were up to 12× slower):
- IRIs: one pass with a class table whose delimiters are bits; resolution that writes
  once, with a fast path for leading `../`; byte-level UTF-8 decoding.
- Decimals: 256-bit products; long division in decimal chunks; a 64-bit fraction for
  output and conversion.
- Dates: values of 32 bytes (instant and timezone).
- Canonicalisation: components, twins, and a search that loops where there is no choice.

The differential tests (`cargo test --release`) pass on the same code: every difference
from Oxigraph is a departure of Oxigraph's from its specification, checked against the
rule, or a documented choice (see the migration plan's status).
