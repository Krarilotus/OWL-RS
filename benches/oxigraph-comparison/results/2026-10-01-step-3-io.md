# Step 3: nrese-rdf-io against the Oxigraph I/O crates, and the engine against the baseline

Run 1 October 2026 on the main development PC (AMD Ryzen 7 7800X3D, 16 threads, 64 GB,
Windows 11), release builds (fat LTO), single runs of 7 rounds each (median). Oxigraph's
crates as released: oxttl 0.2.3, oxrdfxml 0.2.3, oxjsonld 0.2.4 (MIT/Apache-2.0, so these
numbers may be published).

## Readers and writers (`cargo run --release --bin io`)

200,000 generated statements (fixed seed: IRIs from a few namespaces, strings with escapes
and non-ASCII, language tags, typed literals, blank nodes; 30% in named graphs for the
dataset formats), written once by nrese, read by both. "Owned" hands out owned quads, as
Oxigraph does; "borrowed" is nrese's `next_ref` (no allocation per term). Time ratio below 1:
nrese faster. Left: before the improvements of this batch; right: after.

| Case | nrese MB/s | Oxigraph MB/s | ratio before | ratio after |
|---|---:|---:|---:|---:|
| N-Triples, owned | 350 | 148 | 0.47 | 0.42 |
| N-Triples, borrowed | 507 | 151 | 0.32 | 0.30 |

Ratios move by a few percent between runs (the machine also ran an editor and Docker).

**What changed in this batch:**
- **RDF/XML parsing** (1.08–1.31 → 0.84–0.94): the IRI of each element and attribute name
  is checked once per document and cached, not on every occurrence; a scope's base and
  language are shared (`Arc`) instead of copied per element; namespace IRIs are shared;
  an attribute value without entities or whitespace to normalise costs one allocation, not
  three.
- **Turtle and TriG in parallel** (new): `split_slice_for_parallel_parsing` and
  `split_file_for_parallel_parsing` now take Turtle and TriG. A sequential skim (strings,
  IRIs, comments, escapes and nesting only) finds exact statement ends and records every
  directive, so each chunk starts with the prefixes and base in force where it begins.
  oxttl's splitter guesses boundaries (a `.` after which three triples parse) and documents
  that it can fail or give wrong results with directives after the start or Turtle inside
  literals; this one gives the sequential parse's statements for any valid document (tested
  on every W3C Turtle and TriG test in 2, 3 and 8 chunks, and on a document that redefines a
  prefix in its middle, in 2 to 29 chunks).
- **N-Triples and N-Quads writing** (1.09–1.10 → 0.52–0.59): bytes written directly, runs
  that need no escape copied in one piece, instead of through `Display`.

## The engine against the baseline branch

The baseline branch (`baseline/pre-oxigraph-migration`, 79983fe: NRESE on the Oxigraph
libraries) and today's branch (81fcccd), the same examples on the same files, two rounds
alternating (baseline, today, baseline, today).

| Workload | Baseline | Today |
|---|---|---|
| LUBM(10): load 1.27 M triples | 0.39 / 0.40 s | 0.43 / 0.36 s |
| OWL 2 RL closure (830,003 derived) | 0.33 / 0.32 s | 0.32 / 0.30 s |
| 14 LUBM queries with inference (sum, best of 3) | 26.0 / 25.9 ms | 25.5 / 25.2 ms |
| 200 commits, delete p50 / p99 | 0.29 / 0.44 ms; 0.68 / 1.35 ms | 0.23 / 0.34 ms; 0.55 / 1.12 ms |
| 200 commits, insert p50 / p99 | 0.08 / 0.12 ms; 0.16 / 0.30 ms | 0.06 / 0.09 ms; 0.14 / 0.21 ms |
| Olympics: load 1.78 M quads | 0.38 / 0.45 s | 0.43 / 0.42 s |
| Olympics: 13 queries (sum of p50, 5 runs) | 191.1 / 186.2 ms | 191.9 / 196.8 ms |

Equal within noise, which is what this stage should give: the engine still loads through
oxttl until the switch-over (step 5), and the native executor answered nearly every query
before step 1 removed spareval. Commits are about 20% faster. The readers' gains reach bulk
loading with the switch-over. Both datasets are small (they load in under half a second);
the end-to-end comparison of step 5 runs the perf-lab workloads at scale.
