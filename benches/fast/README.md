# The fast suite

Performance tests that run like unit tests: many small cases, one bottleneck or use case
each, 10-300 s per case, the whole suite in under an hour on the main PC. Each case is
checked before its time counts, asserts the plan or engine path it must take, and records
its time and peak memory under a memory cap. A run is compared with an earlier one beyond a
confidence interval, so a regression or a win shows at once. The full benchmarks
([../CATALOG.md](../CATALOG.md)) still run in bulk; this suite doesn't replace them.

```sh
python benches/fast/fast.py list                          the cases: area, semantics, comparators
python benches/fast/fast.py build                         perf lab, DL tools and server, Linux, capped
python benches/fast/fast.py run                           every case, 2 repetitions interleaved
python benches/fast/fast.py run --cases q-cycles,rl-chain --reps 3 --label mine
python benches/fast/fast.py compare benches/baselines/fast/BASE.json benches/baselines/fast/NEW.json
python benches/fast/fast.py compete --cases q-cycles      NRESE beside the systems the case declares
python benches/fast/fast.py clean                         the generated data and scratch
```

| File | What |
|---|---|
| `cases.toml` | the cases: data, semantics, tool and arguments, the metric, checks, route checks, memory cap, comparators, home turf, the §0 wins they measure |
| `fast.py` | the driver: build, data, run, compare, list, clean |
| `compete.py` | `fast.py compete`: each case on its comparators, under the semantics each supports |
| `queries/` | the cases' SPARQL (LUBM's and OWL2Bench's come from `../reasoning/queries`) |
| `rules/`, `shapes/` | the user-rules case's N3 and Datalog programs; the SHACL case's shapes |
| `crates/nrese-store/examples/perf_lab/` | the measuring tool: `generate.rs` (the data), `modes.rs` (commits with readers, clients, canonicalisation), `main.rs` |
| `../baselines/fast/` | committed NRESE results (`<date>-<label>.json`) |

## A case

Every case names, in `cases.toml`:
- **data:** generated by `perf_lab generate KIND key=value ...` (seeded, the same
  everywhere; written once to the volume `nrese-fast-data` with the generator's own
  answers in `.expect.json`), or a file of the dataset volume `nrese-bench-data`;
- **semantics:** what NRESE computes (none, each ruleset, N3 rules, EL, DL);
- **the tool:** the perf lab (load, reasoning, commits with readers, concurrent clients,
  SHACL, queries, canonicalisation) or a DL tool (the hypertableau's consistency, the EL
  classifier, the context core's classification);
- **the metric** it is timed by, and its samples;
- **checks:** the generator's own answers (`expect.KEY`) or pinned counts, compared before
  the time counts. A wrong answer is the run's status (`wrong`), never a time;
- **route checks:** the operators EXPLAIN shows (`has wcoj`, `has group count`), the
  reasoner's rounds (a transitive chain closed by the module in at most 3 rounds, not
  2,500), commits maintained without a rematerialisation, a DL case decided without
  branching (`branch_points == 0`). A case off its route is `off-route`;
- **the memory cap** of its container (no swap): at the cap a case ends as `memory-limit`.
  A case can expect that (`outcome = "memory-limit"`): it then tracks a frontier;
- **comparators:** `system:semantics`, each run only under a semantics it supports;
- **home turf:** the competitor whose documented strength the case is.

Statuses: `ok`, `wrong`, `off-route`, `memory-limit`, `timeout`, `failed`.

## How it measures

- **Linux, capped.** Each case runs in its own container of the pinned Rust image, under
  its memory cap, with the build from the worktree's own target volume. The build is
  `scripts/cargo-guarded.sh` inside that image (`CARGO_BUILD_JOBS`, default 4;
  `NRESE_MEMORY_CAP_GB`, default 8; the container capped to match).
- **Memory:** the container's peak (cgroup `memory.peak`) and the process's (`VmHWM`), after
  the load, after reasoning and at the end.
- **Repetitions:** `--reps 2` by default, interleaved: every case once, then every case
  again in an order rotated by one. Within a repetition the perf lab repeats its
  measurements (`--runs`, `--reason-runs`, `repeat`) and keeps every sample.
- **Comparing:** per case, the samples of all repetitions are pooled per series (a query,
  the rematerialisations, the commits); the metric is the sum of the series' medians.
  `compare` resamples each series (bootstrap, 2,000 rounds, seeded) for a 95 % interval of
  the ratio new/base. A change counts when the interval excludes 1, the ratio is at least
  10 % and the difference at least 2 ms (as PROTOCOL.md §5); 10 % more peak memory (and
  64 MiB) is a regression too. A status change (an `ok` case now `wrong`) comes first.

## Comparators

`fast.py compete` runs each case on NRESE and on the systems it declares, each under the
semantics it names, and on nothing else:
- **SPARQL stores without reasoning** (QLever, Oxigraph, Virtuoso) run the plain cases on
  the same data, and the reasoning cases on NRESE's exported closure (`closure`): the
  query side on equal terms, and what reasoning costs beside it.
- **Reasoners** run under their own semantics: Nemo on OWL 2 RL (the kit's encoding) and on
  the N3 case's Datalog program, Jena on its rules (RDFS, OWL-Horst), HermiT, Openllet and
  Konclude on DL, ELK on EL.
- **Licensed systems** (GraphDB, RDFox, Stardog, AnzoGraph) only with `--licensed` and their
  licences; their results stay in `results/` (git-ignored).

SPARQL systems go through the suite's driver (`benches/suite`, workload `fast`, tier
`CASE~SEMANTICS`), with an NRESE server beside them on the same data, all over HTTP; the DL
reasoners through the DL kit's image. Answer counts must equal NRESE's before a time is
compared. A case whose semantics only NRESE has (rdfs-full, rdfs-plus without a licence,
owl2-ql, compact equality, canonicalisation) has no comparator: its own column.

## Adding a case

1. Data: a generator in `generate.rs` that also computes the answers, or a pinned file.
2. Queries under `queries/<case>/`.
3. An entry in `cases.toml` with its checks, route checks, cap and comparators.
4. `fast.py run --cases NAME --reps 3`: it must end `ok` and take 10-300 s; then the next
   baseline includes it.
5. A win in docs/design/performance.md §0 gets its case in the same commit.
